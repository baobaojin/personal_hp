## 适用场景

- 旅游攻略（去过某地，整理成攻略）
- 技术总结（把某方向的学习笔记整理成一篇文章）
- 经验分享（把工作踩坑整理成可分享的内容）

## 流程

**Step 1：检索相关记录**
- 明确主题（如：XX 城市旅游攻略）
- 检索知识库中与主题相关的所有笔记
- 列出找到的素材，确认是否足够

**Step 2：确认输出结构**
根据内容类型选择结构：

旅游攻略：
```
交通 / 住宿 / 景点 / 美食 / 注意事项 / 费用参考
```

技术总结：
```
背景 / 核心概念 / 关键实现 / 踩坑记录 / 总结
```

经验分享：
```
背景 / 问题 / 解决过程 / 结论 / 适用场景
```

**Step 3：生成内容**
- 基于知识库记录生成，标注哪些是个人经历，哪些是参考资料
- 个人经历：直接描述
- 参考资料：注明来源

**Step 4：写入文件**
- 保存到 `docs/create/<slug>.md`
- frontmatter：

```yaml
---
title: <标题>
category: create
tags: [<类型标签>, <主题标签>]
status: draft
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

## 合理化借口表

| AI 可能犯的错 | 反驳 |
|---|---|
| 用通用知识补充知识库里没有的内容 | 只用知识库里有的记录，没有的部分告知用户需要补充素材 |
| 直接生成内容不先确认素材 | 先列出找到的素材，确认够用再生成 |

## 退出检查

- [ ] 内容来源于知识库记录，不是凭空生成
- [ ] 区分了个人经历和参考资料
- [ ] 已保存到 docs/create/ 下
- [ ] status 为 draft（待用户确认后再改 active）
