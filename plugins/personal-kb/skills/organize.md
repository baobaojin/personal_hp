---
name: organize
description: 给定一批原始材料（文件路径、目录、粘贴内容），自行分析、去冗余、归类、整理后写入知识库，无需逐步确认。
触发词：整理这些文件、整理这个文件夹、把这些内容整理进知识库、归纳这批材料、整理进去。
NOT for：记录单条新内容（用 intake）、总结单篇文章（用 summarize）、查询知识库（用 ask）。
---

## 流程

**Step 1：读取所有材料**
- 读取用户给定的全部文件或内容
- 如果是目录，递归读取所有文件
- 快速扫描全貌，不要逐字精读

**Step 2：分析与去冗余**
- 识别各材料的核心主题
- 找出重复/高度重叠的内容，合并处理，不重复写入
- 识别已经在知识库中有对应文件的内容（先读相关目录），判断是**补充到已有文件**还是**新建文件**
- 过滤掉纯操作流水账、临时备忘、已过时的待办

**Step 3：判断归属**
按以下规则自行判断，不问用户：

| 内容性质 | 归属 |
|---|---|
| 可复用的方法论、设计原则、架构思路 | `docs/knowledge/` |
| 个人项目的进展、决策记录、下一步计划 | `docs/projects/` |
| 职业工作的项目记录、踩坑、日志 | `docs/work/` |
| 操作手册、搭建步骤、可复现的流程 | `docs/knowledge/`（附操作细节） |
| 收藏的外部资料、摘录 | `docs/ref/` |
| 创作草稿、想法 | `docs/create/` |
| 生活相关 | `docs/life/` |

**只在以下情况暂停问用户**：
- 内容横跨两个分类，且无法判断主归属
- 判断不了是补充到已有文件还是新建（已有文件有 50% 以上重叠）
- 涉及是否删除已有内容

**Step 4：整理内容**
- 提取核心内容，去掉冗余表述
- 已有文件：只补充新增的部分，不重写已有内容
- 新建文件：按 intake Skill 的 frontmatter 规范写完整笔记
- 操作步骤类内容：保留代码块和具体命令，这是核心价值

**Step 5：写入知识库**
- 逐个执行写入，先改已有文件，再新建文件
- 每写完一个文件，简短说明"写了什么、放在哪"

**Step 6：整理完成报告**
输出一份简短的总结：
- 修改了哪些已有文件（补充了什么）
- 新建了哪些文件（核心内容是什么）
- 丢弃了哪些内容（为什么）
- 需要用户确认的遗留问题（如有）

## 合理化借口表

| AI 可能犯的错 | 纠正 |
|---|---|
| 遇到每个细节都来问用户 | 只在真正两难的归属决策上暂停，其他自行判断 |
| 把所有材料都新建成独立文件 | 先检查已有文件，能补充的补充，避免知识库碎片化 |
| 保留原材料的所有冗余内容 | 提炼核心，去掉重复表述，操作步骤例外（要保留完整） |
| 把操作手册里的代码精简掉 | 代码和命令是操作类内容的核心价值，必须完整保留 |

## 退出检查

- [ ] 所有材料都已读取并分析
- [ ] 没有重复内容写入多处
- [ ] 已有文件只做补充，没有覆盖原有内容
- [ ] 新建文件有完整 frontmatter
- [ ] 输出了整理完成报告
