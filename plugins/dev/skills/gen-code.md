## 流程

**Step 1：理解需求**
- 明确要实现什么功能
- 输入是什么、输出是什么
- 有没有特殊约束（性能、兼容性、依赖限制）
- 如果需求模糊，先问清楚再写代码

**Step 2：了解项目上下文**
- 读取相关的已有代码，了解：
  - 项目用的语言和框架版本
  - 已有的工具类和公共方法（避免重复实现）
  - 命名风格和代码组织方式
  - 错误处理方式

**Step 3：生成代码**
- 遵循项目已有风格（不引入新的代码风格）
- 复用已有工具类，不重复造轮子
- 包含必要的错误处理
- 命名清晰，复杂逻辑加注释

**Step 4：说明使用方式**
- 如何调用（示例代码）
- 依赖什么（需要安装的包或已有的模块）
- 注意事项（限制条件、已知问题）

**Step 5：建议测试**
- 给出 1-2 个关键测试场景
- 提示用户用 gen-test Skill 生成完整测试

## 合理化借口表

| AI 可能犯的错 | 纠正 |
|---|---|
| 不看已有代码直接写 | 先读项目，避免风格不一致或重复造轮子 |
| 生成代码没有错误处理 | 生产代码必须处理错误，不只是 happy path |
| 生成代码用了项目没有的依赖 | 先确认项目依赖，不擅自引入新包 |

## 退出检查

- [ ] 需求理解准确
- [ ] 遵循了项目已有风格
- [ ] 包含错误处理
- [ ] 有使用示例
- [ ] 说明了依赖和注意事项
